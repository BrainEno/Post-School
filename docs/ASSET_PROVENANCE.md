# Asset provenance and release clearance

This ledger is required for every imported, generated, purchased, downloaded, or externally processed asset used in Post School. An asset being present in the Godot repository, supplied by the owner, generated by an AI tool, or approved visually does not by itself establish commercial-use or redistribution rights.

## Required fields

For each asset or asset group, record:

| Field | Required evidence |
|---|---|
| Asset / Unity path | Stable source and runtime paths |
| Creator / source | Person, organization, tool, or owner-supplied origin |
| Source URL / file origin | Exact URL or supplied-file provenance |
| License / terms | License name/version or terms link |
| Commercial use | Confirmed / denied / unknown |
| Redistribution | Confirmed / denied / unknown |
| Attribution | Exact required credit |
| Modifications | Conversion, editing, generation, processing |
| Approval | Owner decision and date |
| Status | Cleared / restricted / not cleared |

Unknown rights mean **not cleared for public or store release**. Do not infer clearance from successful import, a Git author, a file header, or a previous engine's use.

## Reusing Where Is School assets

- Check the original source ledger: [Where Is School asset provenance](https://github.com/BrainEno/where-is-school/blob/main/docs/ASSET_PROVENANCE.md).
- Review the exact asset entry and any linked audit before copying.
- Do not assume an asset's permission applies to a derivative, converted, generated, or repackaged version.
- Import from approved original source files and document Unity import settings; do not copy Godot `.import` files or caches.
- Keep Blender source files outside runtime folders when appropriate, and do not commit large binaries without an explicit size/hosting decision.
